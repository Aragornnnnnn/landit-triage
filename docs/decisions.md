# 설계 결정

다음에 이 레포를 고칠 사람이 같은 고민을 다시 하지 않게, 정한 것과 이유를 남겨요.

## 카드 먼저, 분석은 스레드로

분석이 끝난 뒤 카드와 분석을 한 번에 올리고 판정에 따라 알림을 무음으로 보내는 안도 있었어요. 장애 알림이 2~4분 늦어지고, 분석이 실패하면 카드까지 늦어질 수 있어서 버렸어요. 카드는 landit-alerts가 지금처럼 바로 올리고, 분석은 독립적으로 붙어요.

## Claude는 Sentry에 직접 접근하지 않음

Sentry MCP를 붙여 Claude가 직접 조회하게 할 수도 있었어요. 대신 스크립트가 자료를 미리 모아 파일로 넘겨요.

- Claude에게 네트워크 도구를 주지 않아도 돼서, Sentry 데이터에 섞인 지시문이 할 수 있는 일이 없어요.
- 무엇을 넘겼는지 실행마다 똑같고, 보관 파일로 다시 볼 수 있어요.
- 같은 사건 후보(앞뒤 2분 이벤트)처럼 지침만으로는 Claude가 잘 안 찾는 자료를 확실히 넘길 수 있어요. 지침에 "찾아 봐"라고만 적었을 때는 테스트에서 두 번 다 못 찾았어요.

## 판정 라벨

"노이즈", "보고만 바꾸기", "수집 안 해도 돼요", "꺼도 돼요", "알림만 정리해요"를 거쳐 **괜한 알림이에요**로 정했어요. 네 라벨이 모두 해요체 상태 문장이고, 처음 보는 사람도 뜻을 바로 읽을 수 있어서예요. ✅ 문제없어요와는 "앞으로도 이 알림이 와야 하느냐"로 갈려요.

## "같이 보자" 프롬프트

처음엔 "이렇게 고쳐 줘" 지시형이었어요. 자동 분석이 틀렸을 때 그대로 코드가 될 수 있어서, 받는 Claude Code가 원인을 다시 확인하고 방향을 제안한 뒤 고르면 테스트부터 쓰는 대화형으로 바꿨어요.

## 구독 토큰, 관리자 한 명

팀원 각자의 구독 토큰을 돌려 쓰는 안도 있었어요. 개인 구독을 모아 팀 공용 봇을 돌리는 건 개인 구독 취지에서 벗어날 수 있고, 쓰기 권한자가 남의 토큰을 쓸 수 있는 문제도 커져서 관리자 한 명의 토큰으로 정했어요. 팀 계정이 생기면 시크릿만 바꾸면 돼요.

## 모델

테스트 분석을 Opus 5.5로 했고 그 품질을 기준으로 지침을 다듬어서 기본값을 Opus 5.5로 뒀어요. 사용량이 부담되면 레포 변수 `CLAUDE_MODEL`만 바꾸면 돼요.

## 코드 버전

웹 이벤트의 Sentry 릴리즈는 landit-fe 커밋 해시라 그 커밋으로 체크아웃해요. BE·AI는 `main`에서 손으로 배포하면서 `be-v1.6.0`, `ai-v1.6.0` 같은 릴리즈를 남겨서, 이벤트 시각 이전에 나온 가장 최근 릴리즈 태그를 봐요. 처음엔 `main`을 봤는데, 머지만 되고 배포되지 않은 코드로 분석할 수 있어서 바꿨어요. 모바일 셸은 앱 버전과 커밋을 잇는 정보가 없어서 `main`을 봐요.

## `--bare`를 쓰지 않음

Claude Code의 `--bare` 모드는 빠르지만 OAuth 토큰을 읽지 않고 API 키만 받아요. 구독으로 돌려야 해서 쓰지 않아요.

## 비용 상한 옵션

Claude Code에 `--max-budget-usd`가 있지만 API 결제 기준이라 구독에서 동작하는지 아직 확인하지 않았어요. 확인 전까지는 하루 상한·도구 횟수·실행 시간으로 막아요.

## 실행을 줄 세우지 않음

워크플로우 `concurrency`로 한 번에 하나씩 돌리려 했지만, GitHub는 같은 그룹의 대기 실행을 하나만 남기고 나머지를 취소해요. 장애로 이슈가 몰리면 분석이 조용히 빠지기 때문에 쓰지 않아요. 대신 동시에 여러 개가 돌면 하루 상한을 한두 건 넘길 수 있어요.

## 분석 요청은 workflow_dispatch로

처음엔 `repository_dispatch`를 썼는데, 이 API는 토큰에 레포 Contents 쓰기 권한이 필요해요.
그 토큰이 새면 레포에 코드를 심어 시크릿을 전부 빼낼 수 있어요.
프라이빗 레포는 무료 플랜에서 브랜치 보호도 안 돼서,
Actions 실행 권한만으로 되는 `workflow_dispatch`로 바꿨어요.

## Claude 출력은 믿지 않고 거른다

웹 앱의 Sentry DSN은 공개라 누구나 가짜 이벤트를 보낼 수 있어요.
에러 메시지에 지시문을 넣어 Claude를 속이는 경우를 가정하고 겹겹이 막아요.

- 도구는 Read·Grep·Glob만, 환경 변수는 구독 토큰만(`env -i`)
- 입력 id 형식 검사, 웹 릴리즈 커밋은 main 히스토리에 있을 때만 체크아웃
- 게시 전에 허용 목록 밖 링크는 무디게, 토큰 모양 문자열은 가림
- 멘션 전부 차단

## 하루 상한 세는 법

- 나보다 **먼저 시작한** 오늘 실행만 세요. 나중 것까지 세면 몰릴 때 서로를 세다 전부 건너뛰어요.
- 끝난 실행은 분석 단계를 시작한 것만, **아직 도는 실행은 분석 중으로** 세요.
  몰릴 때는 모두 가드 단계에 있어서, 시작한 것만 세면 상한이 안 걸려요.
- 상한에 닿으면 더 세지 않아요. 몰릴 때 GitHub API 호출이 늘지 않게요.
- 순서는 시작 시각 기준이에요. 어제 건너뛴 실행을 오늘 다시 돌리면 오늘 것으로 세요.
- 같은 이슈가 동시에 두 번 오면 먼저 온 쪽만 분석해요.
  중복 판단은 "스레드 게시" 성공 기준이고, 카드 없는 시험 실행은 세지 않아요.

## 필요한 파일만 체크아웃

landit-be는 144MB 중 대부분이 데이터 시드 SQL이에요.
체크아웃이 느리고, Claude가 Grep으로 훑으면 토큰을 크게 써요.
sparse checkout으로 시드 SQL과 FE 바이너리(이미지·음원·폰트)를 받지 않아요.

## 넘기는 데이터는 고르기(허용 목록)

처음엔 받은 이벤트에서 위험한 칸을 지웠는데, Sentry 응답은 요청 정보를 `entries` 안에 넣어서 지우는 게 빗나갔어요.
이제는 필요한 칸만 골라 담아요. Sentry가 새 칸을 더해도 새지 않고, 크기도 작아져 매 턴 토큰이 줄어요.

## Claude 격리

`env -i`로 구독 토큰만 넘기고, `config/claude-settings.json`으로 작업 폴더 밖 시스템 경로 읽기를 막아요.
그래도 결과에 토큰 조각이 섞이면 `check-leak`이 실패로 끝내고 보관 파일에서도 지워요.
막는 규칙이 실제 러너에서 먹히는지는 self-check 워크플로우로 확인해요.

## Sentry 응답 1초

Sentry는 웹훅이 1초 안에 응답하길 요구해요.
landit-alerts는 카드까지만 기다려 답하고, 분석 요청은 Vercel `waitUntil`로 응답 뒤에 보내요.
